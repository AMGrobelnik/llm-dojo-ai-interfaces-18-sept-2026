# Output template — the emitted handbook skill

Single source of truth for the generated handbook's **format** (`SKILL.md` owns the **method**); fill at P5. Bundle:

```
aii-handbook-auto-<slug>/
├── SKILL.md      — the handbook: most-recurring/load-bearing claims + the whole lens
├── volatile.md   — version/date-sensitive facts, stamped as_of + applies-to (TTL ≈ half-life)
└── SOURCES.md    — provenance; every [Sn] resolves here (tier + exact-quote columns)
```

## Core conventions — stated ONCE, here

- **Words in proportion to delta — substrate first, then lens, then floor.** Lead with the
  recency-weighted SUBSTRATE (organizing principles + frontier map — the situational awareness the
  consumer's training cutoff denies it, the most reliable + objectively-checkable delta); then the
  LENS (assumptions / open problems / taste / openings — the groundbreaking-work moves); floor
  corrections last. Known-not-universal → ONE terse Ground-rules line. Universal → delete. Thin is on purpose.
- **One tier, compact — NO depth annexes (measured).** Ship only each section's most-recurring / load-bearing
  claims (centrality from the concept×source tallies — ≥3-independent / load-bearing → inline); the verified
  long tail stays in the `.forge/` mining files, unshipped. Measured (CDN Run 2, n=5 directional): the same
  core plus per-topic depth annexes halved clean-novel ideation (80% → 40%) and quadrupled near-misses
  (0.2 → 0.8) — fine-grained depth anchors ideation onto existing work. One compact file serves both pipeline
  stages; execution-stage fine detail is what the consumer's live tools fetch best (P1's rule), so it does not
  justify an annex either. Reopening condition: a fresh A/B showing an execution win with no ideation loss.
- **`SKILL.md` ≤ ~200 lines / ~50 directives** (compliance ≠ line budget); subfiles = `volatile.md` (WHEN line
  in Reference docs) + `SOURCES.md` (provenance), one hop deep.
- **Three states a payload item can ship in:** `✓x` (executed), `[Sn]` (cited), or `⚠️` (candidate).
  **`⚠️` items live ONLY in the Candidate lane — never as normal payload.**
- **The verbatim quote IS the evidence — central, not decorative.** EVERY claim —
  assumption / open-problem / DEEP-contrast / opening lines, ideation AND execution rows,
  Decision-guide bullets, Ground rules, volatile entries — anchors on **≥1 direct quotation**:
  `[Sn]` → `["exact quote"](https://url)` in SOURCES.md; prose paraphrases its quote.
  Cite **permalinks** (release tags, versioned docs, /abs/ pages), never paginating lists.
- **The verifiers are a hard gate, run to flawless:** loop `scripts/verify_quotes.py`
  + `scripts/check_sources.py` → fix (quote, URL, or demote to candidate) → re-run until
  **both exit 0, zero non-OK** — at P4, P5 exit, every regen; never conclude while either fails.
- **The contrastive 5-field row IS the payload format** (a flat fact won't override a
  strong prior — name the prior/direction it displaces); ONE shape for all payload:

  | Naive move | Expert judgment/move | Why (failure prevented) | tier | src |

  Why = the failure class: problematizes-nothing / unimportant-aim / dead-end (ideation) or
  wrong-result / wasted-cost (execution); can't name what's displaced → **not delta → drop.**
  Execution Expert cells: moment-anchored (`<moment>: <action> — <expected value>`; correction-deltas exempt). Cap ~5–9, max 10; overflow → Decision guide.
- **Use the densest form for each kind of info:** a procedure → numbered steps; a principle → a do/don't pair;
  a fact → a `<70`-char table; a gotcha → symptom | cause | fix.
- **Must-hold rules ship as a copyable checklist or validator step**, never prose-only (compliance decays).

<name the SATURATED threads explicitly + say the blank space is NOT here — an explicit REPELLER, not a soft

frame-interrogating question is present — missing one is expensive — but do NOT DUPLICATE one the map already

<one line each + its `[Sn]`, no examples: correct practice a strong model already knows, but a weaker,

## Compose lints (a checklist before you ship)

Treat the Anthropic skill spec as a linter. Check each of these:
- **Basics:** body within budget; description matches the skeleton; reference files one level deep; a table of
  contents on any reference over 100 lines; terms used consistently.
- **Enforcement is structural** — a checklist or validator step, not just emphasis in prose.
- **Laundry-list lint:** a pile of sources with no contrastive claim → send it back to P3.
- **Row-set lint:** two Expert cells that conflict → merge them, or split them by condition.
- **Ceiling lint:** an Assumptions / Open-questions / DEEP line that fits any field, or lacks its quote → cut it or send it back to P3.
- **Blank-space lint (the delta-gate's #1 failure mode; rationale in P3):** every "already crowded / go elsewhere"
  entry AND every gap the map implicitly leaves open, re-checked by a FRESH adversarial search right before ship;
  any "open / not-crowded / no prior work" implication with no dated, fetched saturation check → send it back to P3.
- **Prescription lint:** any line that reads as "do X" / a specific mechanism / a step-by-step method → broaden
  it to the observation behind X (otherwise it causes tunnel vision and is redundant). **This bites hardest on the
  REPELLER and open-question entries: "the open move is X" / "the gap is specifically Y" / "what these do NOT do
  is Z" is a smuggled prescription — state only what is SATURATED (or the bare tension) and STOP; let the consumer
  find the uncrowded move itself.** (Measured in P6: a crowded-lane note that named the open move anchored the
  consumer into a competent-incremental direction, while a free-searching baseline given no such pointer found the
  deeper reframing and won 6/0.)
- **Compactness lint:** an inline claim that isn't among its section's most-recurring/load-bearing → cut it
  (it survives in the `.forge/` mining files; fine-grained depth measurably anchors ideation).

These lints are necessary but not sufficient — only P6 and the human gate actually certify the handbook.
