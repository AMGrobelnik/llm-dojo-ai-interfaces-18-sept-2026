**Shared-origin accounting.** arXiv is a per-work repository, so each arXiv row is its own
registrable origin (co-location on arxiv.org is not shared authorship — no one-vote grouping
applies among them). The non-arXiv origins are each single-source here: `en.wikipedia.org` (S2),
`proceedings.mlr.press` (S18), `nature.com` (S28) — none share an origin with another row.
**Tier:** **L** = landscape / synthesis / result / critique / negative-result / defining-work;
**D** = tertiary self-report / canonical overview (Wikipedia). **Peer-review status is stated per
row**: arXiv rows are **preprints (not peer-reviewed)** unless a venue is named (Logic-LM →
EMNLP-2023 Findings; LINC → EMNLP-2023; ProverQA → ICLR-2025; S18 → NeSy-2025 PMLR;
AlphaGeometry → Nature 2024). Dates are arXiv submission month (`YYMM` id) or the venue year.
The correction rule applies: a critique outranks what it corrects. All quotes re-verified
2026-07-07 with the same extractor `verify_quotes.py` uses.

## Acceptance CQs (standing regen acceptance test — from cqs.md)
Whatever the tool-equipped baseline already answers → Priors omitted. The handbook's delta is the
frontier map + crowded list + open questions, not these:
1. In LLM+solver pipelines (Logic-LM/LINC), LLM = semantic parser (NL→symbolic); solver = deterministic inference. [S24][S26]
2. Logic-LM self-refinement uses the symbolic solver's error messages. [S24]
3. NL2FOL's named key challenge = integrating implicit background knowledge. [S32]
4. Three formal targets NL is translated into: FOL, SAT/SMT, ASP/Prolog (any three). [S24][S26]
5. Kautz type for "neural interprets → symbolic reasons" = type 3 "Neural | Symbolic" (text2logic). [S2]
6. Kautz coupling-tightness maps verifiability (hard logic) vs learnability (end-to-end). [S2]
7. DeepProbLog = probabilistic logic programming with neural predicates, differentiable. [S1][S2]
8. Scallop vs DeepProbLog = Datalog + provenance semirings + top-k (more time-efficient). [S2]
9. Logic Tensor Networks = differentiable real-valued FOL (fuzzy tensor grounding). [S1][S2]
10. Pre-LLM logical-reasoning benchmarks: RuleTaker, ProofWriter, CLUTRR (also ProntoQA/FOLIO). [S25]
11. Template benchmarks: scalable but simplistic / low-diversity, shortcut-learnable. [S25]
12. Hand-curated (FOLIO/MALLS): small + contamination-prone + annotation errors. [S13][S25]
13. ProverGen makes ProverQA via LLM generation + symbolic prover; chain-accessible. [S25]
14. SOTA LLMs do NOT solve ProverQA easily — struggle even with CoT. [S25]
15. "Scope laundering" = reporting a solver-inconsistent verdict without executing the reasoning. [S5]
16. Higher benchmark accuracy does NOT imply faithful reasoning. [S5][S6]
17. Two other failure modes: implicit-constraint blindness; program-synthesis (bad solver code). [S5]
18. Why an upper ontology: supply background/taxonomic structure for terms not explicit in text. [S16][S18]
19. Main computational bottleneck for NeSy at scale = knowledge extraction. [S2]
20. Garcez & Lamb definition: principled integration of neural learning + symbolic KR & reasoning. [S4]
